# STM32F407 机械臂驱动移植与修改指南

## 1. 本次移植结果

目标工程：`D:\STM32\HAL\26`

目标芯片：STM32F407VET6，168 MHz，HAL 库，FreeRTOS/CMSIS-RTOS V2。

原模板是 STM32F103 标准库工程，舵机使用定时器中断模拟多路 PWM。该实现不能直接复制到 F407 HAL 工程。本次去掉原夹爪舵机，并将其余舵机顺延编号，重新实现为：

- 5 路硬件 PWM，50 Hz、1 us 分辨率；
- USART1 视觉口采用 DMA2 Stream2 Channel4 接收；
- USART2 上位机调试口采用 DMA1 Stream5 Channel4 接收；
- 使用 `HAL_UARTEx_ReceiveToIdle_DMA()` 完成 DMA＋串口空闲中断接收；
- FreeRTOS 下拆分为通信、运动、安全三个任务；
- USART1支持第一问固定52字节包、半包、粘包、连续包和单字节ACK，USART2使用可读文本命令；
- 运动任务采用 20 ms 周期三次平滑插值；
- 具有舵机角度限位、STOP、电磁铁最长吸合时间和可选急停/通信看门狗；
- K230发送四片抓放坐标与旋转量，F407负责逆解、自动抓放、实时PWM与安全执行。

> 当前版本已实现第一问自动拼图。详细参数、逆解公式、动作状态机和调试方法见
> `docs/第一问逆解与自动拼图说明.md`。

## 3. 引脚与接线

### 3.1 五路舵机

| 新编号 | 原编号 | 机械作用 | STM32 外设 | STM32 引脚 |
|---|---:|---|---|---|
| 舵机 1 | 2 | 电磁铁末端旋转 | TIM1_CH2 | PE11 |
| 舵机 2 | 3 | 腕部/末端俯仰 | TIM1_CH3 | PE13 |
| 舵机 3 | 4 | 肘部 | TIM1_CH4 | PE14 |
| 舵机 4 | 5 | 肩部 | TIM8_CH1 | PC6 |
| 舵机 5 | 6 | 底座旋转 | TIM8_CH2 | PC7 |

原夹爪舵机对应的 TIM1_CH1/PE9 已停用，不输出 PWM。当前编号按原来的
2～6 号整体前移，不要求改变这五路舵机的物理接线。

PWM 为 50 Hz，计数分辨率 1 us。默认逻辑角度 0～180.0° 映射到 500～2500 us。

不要用开发板 5 V 引脚直接给五个大扭矩舵机供电。建议：

- 舵机使用独立 5～8.4 V 大电流电源，电压按舵机型号确定；
- 舵机电源负极、STM32 GND、K230 GND、USB-TTL GND 必须共地；
- 每组舵机电源入口放置足够的电解电容；
- STM32 只输出 PWM 信号；
- 首次上电先拆下舵盘或断开连杆，确认方向和限位后再装机械结构。

### 3.2 USART1：K230 视觉串口

| 信号 | STM32F407 | 连接 |
|---|---|---|
| USART1_TX | PB6 | 接 K230 RX |
| USART1_RX | PB7 | 接 K230 TX |
| GND | GND | 接 K230 GND |

默认参数：115200 bit/s，8 数据位，1 停止位，无校验，无流控，3.3 V TTL。

RX 使用 DMA2 Stream2 Channel4，USART1 和 DMA 中断优先级均为 6。当前 `FreeRTOSConfig.h` 的 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` 是 5，因此不要把这两个中断改成 0～4，否则在中断中调用 `xQueueSendFromISR()` 会违反 FreeRTOS 规则。

### 3.3 USART2：电脑上位机调试串口

| 信号 | STM32F407 | 连接 |
|---|---|---|
| USART2_TX | PA2 | 接 USB-TTL RX |
| USART2_RX | PA3 | 接 USB-TTL TX |
| GND | GND | 接 USB-TTL GND |

默认参数同样为 115200 bit/s、8N1、无流控、3.3 V TTL。RX 使用
DMA1 Stream5 Channel4。不要直接连接传统 RS-232 电平，也不要把 5 V
TTL 信号直接接入 STM32。

USART1保留供K230使用的二进制CRC协议；USART2改为电脑调试专用的
ASCII文本命令行。两路拥有独立DMA缓冲区与FreeRTOS队列，数据不会
互相拼接。USART2可直接发送`SERVO 5 100 2000`，不再使用HEX协议帧。

### 3.4 电磁铁与急停

| 功能 | 默认引脚 | 说明 |
|---|---|---|
| 电磁铁控制 | PD12 | 高电平有效，只能驱动 MOSFET/驱动板输入 |
| 拼图完成指示 | PE9 | 高电平有效，接限流LED或驱动板输入 |
| 急停输入 | PD13 | 默认关闭；启用后为低电平有效、内部上拉 |

电磁铁线圈不能直接连接 STM32 GPIO。必须使用逻辑电平 MOSFET 或驱动模块，并在线圈两端配置续流二极管。

舵机 1 和电磁铁是两个不同的控制量：舵机 1（PE11）只负责铁片吸附后
末端的旋转角度；PD12 才负责电磁铁吸合或释放。吸住铁片后需要同时保持
PD12 为有效电平，再移动舵机 1。

## 4. FreeRTOS 任务结构

| 任务 | 优先级 | 周期/阻塞方式 | 职责 |
|---|---:|---|---|
| ArmSafety | 48 | 20 ms | 急停、电磁铁超时、可选通信超时 |
| ArmMotion | 40 | 动作中 20 ms | 平滑插值、输出五路目标角、STOP 响应 |
| ArmComm | 32 | 两路串口各阻塞最多 5 ms | USART1计划解析与ACK、USART2文本CLI |
| ArmPuzzle | 30 | 计划到达后运行 | 预解算、四片抓取/搬运/放置状态机 |
| defaultTask | 24 | 1000 ms | CubeMX 保留空闲任务 |

优先级越大越高。四项机械臂任务栈空间约 8 KB，各队列和任务控制块仍在
当前15 KB FreeRTOS heap容量内。

UART 中断只做三件事：

1. 取得 DMA 本次接收长度；
2. 把数据块复制到 FreeRTOS 队列；
3. 立即重新启动 DMA。

52字节协议解析、文本命令解析、命令处理和串口发送都在`ArmComm`任务完成，
不在中断里做耗时运算。

## 5. K230 与 F407 的职责划分

> 本节已由第一问方案更新。K230不再发送五路关节角；当前正式数据流见
> `docs/第一问逆解与自动拼图说明.md`。

推荐数据流：

```text
K230 拍照与识别
    ↓
像素坐标 → A4纸毫米坐标
    ↓
生成四片抓取XY、放置XY和旋转量
    ↓
发送固定52字节计划并等待0xAC
    ↓
F407预解算并自动执行四片抓放
    ↓
PE9完成指示，USART2输出DONE PUZZLE
```

第一问按题目要求一键启动、无人干预，当前采用识别一次后执行完整计划。

## 6. USART1视觉二进制协议与USART2文本调试

当前USART1正式协议为固定52字节包和单字节 `0xAC` ACK，详见
`docs/第一问逆解与自动拼图说明.md`。USART2文本调试命令仍然有效。

<details>
<summary>早期通用关节控制协议存档（当前USART1不启用，请勿用于K230）</summary>

以下早期协议中的多字节数值采用小端格式；第一问52字节协议则采用大端，
两者不能混用。

### 6.1 帧格式

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | 0xAA | 帧头 1 |
| 1 | 1 | 0x55 | 帧头 2 |
| 2 | 1 | version | 当前为 0x01 |
| 3 | 1 | sequence | 请求序号，回复原样返回 |
| 4 | 1 | command | 命令字 |
| 5 | 1 | payload_length | 0～64 |
| 6 | N | payload | 命令数据 |
| 6+N | 2 | CRC16 | 低字节在前 |

CRC 算法为 CRC-16/CCITT-FALSE：初值 `0xFFFF`，多项式 `0x1021`，不反射，无最终异或。计算范围从 `version` 到 payload 末尾，不包括 `AA 55` 和 CRC 本身。

### 6.2 K230/电脑上位机发给 F407 的命令

| 命令 | 值 | payload |
|---|---:|---|
| PING | 0x01 | 无 |
| MOVE_JOINTS | 0x10 | 5×`int16` 角度（0.1°）＋`uint16` 时间 ms，共 12 字节 |
| MAGNET | 0x11 | 0=关闭，1=吸合 |
| HOME | 0x12 | 无：默认时间；或 `uint16` 时间 ms |
| STOP | 0x13 | 无；停止运动并关闭电磁铁 |
| GET_STATUS | 0x14 | 无 |

例如目标角 `[90.0, 45.0, 120.0, 90.0, 30.0]`，动作时间 1500 ms，则 MOVE payload 中依次放入：

```text
int16: 900, 450, 1200, 900, 300
uint16: 1500
```

### 6.3 F407 回复

| 回复 | 值 | payload |
|---|---:|---|
| ACK | 0x80 | 原命令 1 字节＋结果码 1 字节 |
| DONE | 0x81 | 原命令 1 字节＋执行结果 1 字节 |
| STATUS | 0x82 | 状态字段，见下表 |
| ERROR | 0xFF | 原命令 1 字节＋错误码 1 字节 |

MOVE/HOME 被动作队列接受时先返回 ACK，动作结束后再返回相同 sequence 的 DONE。ACK 只表示“已入队”，不表示机械臂已经到位。

STATUS payload：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | flags：bit0 正在运动，bit1 电磁铁开，bit2 急停有效 |
| 1 | 10 | 当前五关节角度，5×`int16`，单位 0.1° |
| 11 | 2 | UART DMA 数据块丢弃计数，最大 65535 |
| 13 | 2 | UART 错误计数，最大 65535 |

STATUS payload 总长度为 15 字节。

结果码定义：

| 值 | 含义 |
|---:|---|
| 0 | OK |
| 1 | payload 长度错误 |
| 2 | 协议版本错误 |
| 3 | CRC 错误，当前解析器直接丢弃该帧 |
| 4 | 未知命令 |
| 5 | 舵机角度超限 |
| 6 | 动作队列已满 |
| 7 | 忙 |
| 8 | 硬件输出失败 |
| 9 | 动作被 STOP 中止 |
| 10 | 急停触发 |
| 11 | 电磁铁吸合超时 |
| 12 | 通信超时 |
| 13 | 参数值错误 |

### 6.4 K230 端 Python/CanMV 打包参考

```python
import struct

VERSION = 1

def crc16_ccitt(data):
    crc = 0xFFFF
    for value in data:
        crc ^= value << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc

def make_frame(seq, cmd, payload=b""):
    body = bytes((VERSION, seq & 0xFF, cmd, len(payload))) + payload
    crc = crc16_ccitt(body)
    return b"\xAA\x55" + body + struct.pack("<H", crc)

def make_move(seq, angles_deg, duration_ms):
    # round 后转为 0.1 度；必须保证每个角度在 F407 配置的限位内
    if len(angles_deg) != 5:
        raise ValueError("MOVE_JOINTS requires exactly 5 angles")
    angles_x10 = [round(angle * 10) for angle in angles_deg]
    payload = struct.pack("<5hH", *angles_x10, duration_ms)
    return make_frame(seq, 0x10, payload)

# uart.write(make_move(1, [90, 45, 120, 90, 30], 1500))
```

K230 接收端同样需要按 `AA 55`、长度和 CRC 解析，不能假设一次 `uart.read()` 正好得到一帧。

### 6.5 电脑端USART2文本调试

VOFA+或普通串口助手设置为115200、8N1，关闭“HEX发送”，直接发送ASCII
字符串。命令不区分大小写；可以带`\r\n`，也可以不带换行单次发送。

| 文本命令 | 作用 |
|---|---|
| `PING` | 通信测试，回复`OK PONG` |
| `SERVO 5 100 2000` | 只控制5号底座到100.0°，用时2000 ms |
| `BASE 100 2000` | 底座舵机快捷命令，等价于上一条 |
| `MOVE 90 90 90 90 100 2000` | 设置五路角度与动作时间 |
| `HOME 2000` | 2000 ms回到五路HOME角度 |
| `MAGNET ON` / `MAGNET OFF` | 电磁铁吸合/释放 |
| `GOTO 105 0 20 0 2000` | 按A4坐标逆解并移动，不自动控制电磁铁 |
| `CALIB CHECK` | 只解算A4六个边界点，不驱动机械臂 |
| `CALIB START` | 先到P1，再以15mm/s沿完整A4边框闭合巡边后回HOME |
| `CALIB POINT 3` | 单独移动到P3并停留，点号范围1～6 |
| `CALIB STATUS` | 查询校准状态、当前点和失败点 |
| `CALIB STOP` | 停止校准动作 |
| `STATUS` | 查询运动、电磁铁、五路角度及串口错误 |
| `STOP` | 停止动作并关闭电磁铁 |
| `HELP` | 打印命令列表 |

复位并启动FreeRTOS后，USART2会输出：

```text
READY ARM_CLI
SEND HELP FOR COMMANDS
```

例如发送：

```text
BASE 100 2000
```

立即回复命令已进入动作队列：

```text
OK SERVO 5 TARGET=100.0 TIME=2000
```

动作完成后回复：

```text
DONE MOVE OK (0)
```

如果上一个动作尚未完成，会回复`ERR SERVO BUSY (7)`。输入旧的
`AA 55 ...`二进制数据会回复`ERR USART2 TEXT_ONLY; SEND HELP`。

工程也提供文本串口测试工具`tools/arm_pc_serial.py`：

```powershell
python -m pip install pyserial
python tools/arm_pc_serial.py --port COM5 ping
python tools/arm_pc_serial.py --port COM5 base 100 --duration 2000
python tools/arm_pc_serial.py --port COM5 servo 1 90 --duration 1000
python tools/arm_pc_serial.py --port COM5 calib check
python tools/arm_pc_serial.py --port COM5 calib point 3
python tools/arm_pc_serial.py --port COM5 calib start
python tools/arm_pc_serial.py --port COM5 status
```

将`COM5`替换为USB-TTL对应的串口号。

## 7. 最常修改的参数

打开 `App/Inc/arm_config.h`。

### 7.1 调整单个舵机方向

```c
#define ARM_SERVO2_REVERSED 1U
```

`0U` 为正向，`1U` 为反向。不要通过交换电源线改变舵机方向。

### 7.2 调整机械限位和零位

```c
#define ARM_SERVO2_MIN_ANGLE_X10   250   /* 25.0° */
#define ARM_SERVO2_MAX_ANGLE_X10   1450  /* 145.0° */
#define ARM_SERVO2_HOME_ANGLE_X10  900   /* 90.0° */
```

逻辑角度可以根据机械臂模型定义，不要求五个关节都使用完整 0～180°。`HOME` 必须落在 min/max 之间。

### 7.3 调整脉宽

```c
#define ARM_SERVO2_MIN_PULSE_US  600U
#define ARM_SERVO2_MAX_PULSE_US  2400U
```

不同舵机的安全脉宽不同。若出现顶死、啸叫或大电流，立即断电并缩小范围。脉宽修改不会改变 K230 使用的逻辑角度单位。

### 7.4 调整速度

K230 在每个 MOVE 命令中传入 `duration_ms`。F407 会让五个关节同时开始、同时结束。持续时间上限由：

```c
#define ARM_MOTION_MAX_DURATION_MS 30000U
```

控制。运动刷新周期默认为 20 ms，与 50 Hz 舵机 PWM 匹配，一般不应改得更快。

### 7.5 打开急停或通信看门狗

```c
#define ARM_ESTOP_ENABLED          1U
#define ARM_COMM_WATCHDOG_ENABLED  1U
```

启用通信看门狗后，K230 必须在超时时间内持续发送有效帧，通常每 200～500 ms 发送一次 PING。

### 7.6 不接视觉时的单舵机调零模式

调零参数位于 `App/Inc/arm_config.h`：

```c
#define ARM_ZERO_CALIBRATION_MODE      1U
#define ARM_ZERO_CALIBRATION_SERVO     1U
#define ARM_ZERO_CALIBRATION_PULSE_US  1500U
```

当前工程已经退出固定调零模式：

```c
#define ARM_ZERO_CALIBRATION_MODE 0U
```

USART1、USART2、动作任务和安全任务都会启动，上位机可以控制五路舵机。
如果需要再次逐路调零，临时改成 `1U`；此时两个串口和机械臂 FreeRTOS
任务都不会启动，只给选中的一路输出固定脉宽。

调零时需要区分三个概念：

- 电气中位：舵机接收 1500 us；
- 机械零位：舵盘和机械臂关节实际安装基准；
- 软件 HOME：当前协议使用 90.0° 表示中位/初始姿态。

推荐逐路操作：

1. 关闭舵机电源，拆下当前舵机的舵盘或断开连杆。
2. 只连接当前一路舵机；舵机使用独立电源，电源负极与 STM32 共地。
3. 保持 `ARM_ZERO_CALIBRATION_PULSE_US=1500U`，编译并下载程序。
4. 打开舵机电源，等待舵机停在电气中位。
5. 不转动舵机轴，把舵盘按最接近机械基准的齿位重新安装。
6. 关闭舵机电源后再安装螺钉和连杆，不要带电强扭输出轴。
7. 将 `ARM_ZERO_CALIBRATION_SERVO` 改为 2，重新编译下载，依次完成 2～5 号舵机。
8. 五路完成后把 `ARM_ZERO_CALIBRATION_MODE` 改回 `0U`，重新完整编译。
9. 在正常模式下使用较慢的 HOME 动作测试方向，再缩小每个关节的 min/max。

舵盘齿数造成的小角度误差，优先通过连杆长度或 HOME 角度微调。除非
舵机规格明确允许，否则不要为了追求机械零位而把脉宽调到接近
500/2500 us；那可能让舵机撞到内部限位。

## 8. 首次上电调试顺序

1. 不接舵机电源，只给 STM32、K230 和 USB-TTL 上电，确认工程正常运行。
2. 电脑通过USART2发送文本`PING`，确认收到`OK PONG`，再测试USART1。
3. 读取 STATUS，确认 UART 错误和丢包计数为 0。
4. 拆下舵盘或断开连杆，只接一个舵机和限流电源。
5. 发送 HOME，确认 90° 方向；若方向相反，修改对应 `REVERSED`。
6. 分别测试较小角度范围，逐步确定 min/max 和安全脉宽。
7. 五路逐个完成标定后，再安装舵盘和连杆。
8. 先用 2～3 s 的慢动作测试，再逐渐缩短时间。
9. 最后接电磁铁驱动板，测试 MAGNET 和最长吸合时间保护。
10. 机械结构完整后再让 K230 执行自动抓取路径。

任何时候出现堵转、结构碰撞、异常复位或电源压降，都应先断开舵机电源，不要靠软件 STOP 代替物理断电。

## 9. Keil 与 CubeMX 注意事项

Keil 工程已经增加：

- `../App/Inc` 与 `../BSP/Inc` 头文件路径；
- `Application/MechanicalArm` 源码组；
- `Application/MechanicalArm/BSP` 源码组；
- USART1 视觉口与 USART2 上位机调试口 BSP；
- HAL UART 驱动 `stm32f4xx_hal_uart.c`；
- `HAL_UART_MODULE_ENABLED`。

`26.ioc` 已与当前硬件分配同步，包含 TIM1、TIM8、USART1、USART2、
两路 USART RX DMA、DMA/USART 中断及电磁铁 GPIO。时钟树采用
HSE 8 MHz、SYSCLK 168 MHz、PLLQ=7（48 MHz 域）。

当前运行代码仍由 BSP 保存独立的定时器、串口和 DMA 句柄；
`.ioc` 用于记录引脚和外设配置，并保证以后打开 CubeMX 时不会丢失硬件分配。

如果以后重新生成 CubeMX 工程，请检查：

1. `main.c` 的 USER CODE 区仍调用 `ArmApp_HardwareInit()`；
2. `freertos.c` 的 USER CODE 区仍调用 `ArmApp_RtosInit()`；
3. Keil 中 App/BSP 两个组没有被移除；
4. Include Path 仍包含 `../App/Inc;../BSP/Inc`；
5. `stm32f4xx_hal_conf.h` 仍启用 `HAL_UART_MODULE_ENABLED`；
6. HAL UART 源文件仍在工程中；
7. CubeMX 没有把 PE11、PE13、PE14、PC6、PC7、PB6、PB7、PA2、PA3、PD12 分配给其他外设；
8. USART1_RX 仍为 DMA2 Stream2 Channel4，USART2_RX 仍为 DMA1 Stream5 Channel4；
9. CubeMX 生成的 USART 与 DMA 中断优先级不高于 FreeRTOS
   `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` 的限制（当前 `.ioc` 为 5，
   BSP 运行时配置为 6，二者都可安全调用 FromISR API）。

不要同时启用 CubeMX 生成的 TIM1/TIM8/USART1/USART2 初始化和当前 BSP 初始化。若决定以后全部改成 CubeMX 管理，应先让 BSP 改为使用 CubeMX 生成的外设句柄，再删除 BSP 内部的硬件初始化。

当前 USART1、USART2、DMA1 Stream5 和 DMA2 Stream2 的中断入口定义在
`BSP/Src/bsp_uart_dma.c` 与 `BSP/Src/bsp_debug_uart_dma.c`。重新生成代码后，
若 CubeMX 又在 `Core/Src/stm32f4xx_it.c` 中生成同名函数，必须删除 Core
中的四个重复入口，否则链接器会报告 `multiply defined`。

### 9.1 EIDE 项目

EIDE 不直接读取修改后的 `26.uvprojx`。为避免旧的
`MDK-ARM/.eide` 导入配置覆盖新增模块，本工程使用独立入口：

```text
D:\STM32\HAL\26\26-eide.code-workspace
```

其持久配置位于工程根目录：

```text
D:\STM32\HAL\26\.eide\eide.yml
```

打开新工作区后，展开 `项目资源 → Application → MechanicalArm`，
即可看到 App、BSP 和 Documentation。该配置已经包含 App/BSP 头文件
路径、HAL UART 源文件，以及 STM32F407VET6 的 512 KB Flash、
112 KB SRAM1 和 16 KB SRAM2 布局。

EIDE 的构建输出位于：

```text
EIDE-build/26/26-F407-Arm.hex
```

不要再使用旧的 `MDK-ARM/26.code-workspace` 进行 EIDE 构建，也不要从
旧版 `uvprojx` 覆盖导入根目录 EIDE 项目，否则可能重新生成缺少
App/BSP 的文件索引。

## 10. 后续扩展建议

- 增加限位开关：在 `bsp_safety_io` 中增加输入，再由 `arm_safety` 停止对应动作。
- 增加舵机反馈：普通 PWM 舵机没有真实角度反馈，STATUS 当前返回的是“命令角度”，不是编码器实测角度。
- 增加抓取动作序列：可在 K230 上组织 HOME、预抓取、下降、吸合、抬升、搬运、释放等状态机。
- 增加流式视觉伺服：新增“覆盖目标”命令与单元素邮箱，不要使用现有 FIFO 动作队列堆积旧目标。
- 更换串口或 PWM 引脚：修改 `BSP/Src/bsp_uart_dma.c`、`BSP/Src/bsp_debug_uart_dma.c` 或 `BSP/Src/bsp_servo_pwm.c`，同时核对 F407 数据手册中的复用功能和 DMA 映射。
